# RENTIX_BOARD — заполнение доски реальными однушками (что делаем / что сделали / ревью)

Живой холод-старт: доска `ChirieBot` (bot `@gaseste_casa_bot`, канал `@gaseste_casa`,
Mini App) была пуста (0 активных). Мы наполнили её **реальными объявлениями аренды
однокомнатных квартир в Кишинёве**, спарсенными с портала **rentix.md**.

Фокус доски совпадает идеально: `FOCUS_DEAL=rent`, `FOCUS_ROOMS=1`, `DEFAULT_CURRENCY=EUR`.

---

## 1. Что мы делаем (задача)

Взять реальные объявления аренды однушек из внешнего источника и показать их на доске,
чтобы у нового посетителя было «что смотреть», пока не пойдут объявления от реальных
владельцев. Источник должен парситься с нашего сервера, без браузера и без прокси.

## 2. Что сделали (итог)

- Написали парсер `deploy/test_data/parse_rentix.py` (работает на VPS).
- Наполнили доску **10 реальными однушками** (550–800 €), все `active`.
- Опубликовали все 10 в канал + они видны в Mini App (`{"active": 10}`).
- Прогнали ревью результата и пофиксили найденные дефекты (см. §5–6).
- Сделали перезапуск идемпотентным и flood-safe (`deploy/test_data/seed_rentix.sh`).

## 3. Все возможности парсера/пайплайна (ничего не упущено)

**Источник и доступ**
1. rentix.md, раздел длительной аренды квартир: `https://rentix.md/ro/search/chirie/apartament/1-camera/chisinau?page=N`.
2. Серверный HTML + JSON-LD (`Product`, `ItemList`) — видно роботу без JS/браузера/прокси.
3. Работает напрямую с нашего VPS (89.40.3.91). Прокси не нужен.

**Извлекаемые поля (на карточку)**
4. `id` + каноническая ссылка объявления (`/ro/chirie/.../apartament-chisinau-<id>`).
5. Комнатность (`N-camere` → `rooms`).
6. Площадь (`N m²` → `area`).
7. Этаж (`etaj X din Y` → `floor` / `floors`).
8. Цена + валюта (`1 000 €` / `lei` → `price` + `EUR`/`MDL`).
9. Район/сектор из адресной строки (`Centru`, `Rîșcani`, `Botanica`, …).
10. Адрес/улица.
11. Фото — webp-слайды карусели.

**Обработка**
12. webp → JPEG через Pillow (`features.check("webp") == True`), т.к. Telegram `send_photo`
    принимает только JPEG/PNG. Скачивание в `images/rentixNN_k.jpg`.
13. Районы RO → RU (таблица `_DIST`, с вариантами `â/î`): Центр/Рышкановка/Ботаника/
    Буюканы/Чеканы/Телечентр/Будешты/Бачой/Ватра/Încub.
14. Унификация префикса улицы: `str./strada/ul.` → `ул.`, `bd./bulevardul` → `бул.`,
    `calea` → `калеа`; сектор и город отрезаются (район уже есть в шапке).
15. Фильтры: только однушки (`rooms==1`), потолок цены `RENTIX_PRICE_MAX` (1600 €),
    сортировка «сначала дешёвые», `RENTIX_TARGET` (10), `RENTIX_PAGES` (4), `RENTIX_PHOTOS` (3).
16. Честность: `is_demo=0` (это реальные сдачи), телефон НЕ выдумывается и НЕ парсится,
    контакт — только кнопка `🔗 Сайт` → живое объявление rentix; в тексте —
    `Источник: rentix.md`.
17. Идемпотентный перезапуск: `seed_rentix.sh` сначала вычищает старые карточки rentix
    (сообщения в канале + строки в БД), потом парсит и публикует заново — без дублей.
18. Flood-safe публикация: ловит `TelegramRetryAfter`, спит `retry_after+5` c, пауза между
    карточками; отдельный шаг «finish» докачивает то, что не ушло с первого раза.
19. Атомарность канала: если сообщение с кнопками отклонено — только что выложенный альбом
    удаляется (защита от «осиротевших» фото-постов без кнопок).
20. Работает целиком на VPS через `deploy/run.ps1`; на генерируемые `rentix_listings.json`
    и фото-пул в git не попадает (это runtime-артефакты).

**Возможности бота, которые задействует заполненная доска**
21. Mini App: лента с focus-локом (rent/1 комната), поиск/фильтры/сортировка, карточка с
    фотоальбомом, счётчики `views`/`web_contact`, подписка на поиск (alerts).
22. Автопостинг в канал, шеринг-кнопка, кнопка «Разместить своё объявление».
23. Буст/подсветка «Срочно», кошелёк MDL и card-rail (сейчас `CARD_ENABLED=False`).

## 4. Как запустить / обновить доску

```powershell
# налить/обновить 10 однушек (парсинг + скачивание фото + публикация, идемпотентно):
powershell -File deploy\run.ps1 deploy\test_data\seed_rentix.sh "bash /opt/imobiliare/test_data/seed_rentix.sh" -RemoteDir /opt/imobiliare/test_data

# изменить объём/фильтры, например 25 карточек до 700 €:
#   задать env на VPS перед запуском: RENTIX_TARGET=25 RENTIX_PRICE_MAX=700
```

## 6. Узкие места и риски (что НЕ идеально)

1. **Telegram flood на канале.** ~1 карточка за `(retry_after 20–34с)` + паузы. Заливка
   30+ карточек займёт много минут и требует pacing/довода. Это главное операционное узкое место.
2. **Один источник.** Сейчас парсится только rentix. `9999.md` лежит (DNS), `xmetr` = 403
   (Cloudflare). Если rentix сменит вёрстку — парсер упадёт. Нужен второй источник для надёжности.
3. **Эфемерный Mini App URL.** `WEBAPP_URL=…trycloudflare.com` — быстрый туннель, который
   умирает/меняет хост. Для настоящего продакшена нужен стабильный домен (nginx), иначе
   кнопка «Смотреть все объекты» и Mini App отваливаются. Это **самый большой production-риск**.
4. **Устаревание карточек.** Сиды вставляются сразу `active`, `expires_at` не задан → живут
   вечно. Снятая на rentix квартира останется на доске. Нужен периодический refresh
   (`seed_rentix.sh` пересобирает доску заново) либо простановка `expires_at`.
5. **Юридическая зона.** Репост чужих объявлений = серая зона по ToS. Смягчено: атрибуция
   источника + кнопка на живое объявление + нет слитого телефона. Это холод-старт, а не
   постоянная модель: как только пойдут opt-in владельцы, сиды надо выключить/архивировать.
6. **Фото с водяным знаком.** У rentix изображения без явного водяного знака (в тестах
    чисто), но риск на других порталах есть.
7. **Модерация.** Сиды пишутся в обход `pending` (сразу `active`) — ок для наполнения,
   неприменимо к объявлениям пользователей.
8. **`is_demo=0`** → приветственная плашка «это демо» исчезает; новый пользователь понимает,
   что карточки агрегированные, только из строки «Источник: rentix.md» внутри карточки.

## 7. Готовность beta/production

- **Beta/демо — готово:** доска живая (10 карточек), канал и Mini App согласованы, рендер чистый,
  кнопки работают, перезапуск идемпотентен и flood-safe.
- **Перед масштабированием:** стабильный домен Mini App вместо trycloudflare; второй источник
  парсинга; периодический refresh/expire сидов; решение по ToS (или переход на opt-in владельцев).

## 8. Что в репозитории

- `deploy/test_data/parse_rentix.py` — парсер (создаёт `rentix_listings.json` + качает фото).
- `deploy/test_data/seed_test_data.py` — универсальный сид/паблишер (принимает путь к json).
- `deploy/test_data/seed_rentix.sh` — идемпотентный оркестратор (чистка → парсинг → публикация → finish).
- `bot/render.py` — форматирование чисел (`n()`) для чистых карточек.
- `bot/publish.py` — `url`-кнопка вместо `web_app` в канале + откат альбома при ошибке + текст CTA.
